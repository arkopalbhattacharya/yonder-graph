# Audit & Compliance

Enterprise IT operations require total transparency. Every action, governance decision, and inference generated by Yonder Graph is immutably recorded in PostgreSQL.

## The Audit Data Model
All events are stored in the `agent_audit_logs` table (defined in `backend/audit/models.py`).

Fields captured:
- `session_id`: UUID tying together multi-agent operations for a single incident.
- `timestamp`: UTC execution time.
- `agent_name`: Which agent in the ADK squad performed the action.
- `action_type`: E.g., `CYPHER_QUERY`, `SQL_BINDING`, `SAFETY_CHECK`, `TRIAGE_COMPLETE`.
- `input_payload` / `output_payload`: Full JSON snapshots of the data processed.
- `execution_time_ms`: Agent latency.
- `status`: `SUCCESS`, `FAILED`, `BLOCKED_BY_GOVERNANCE`.

## Governance Intercept Logging
When Tier 2 (Oracle SQL Validator) blocks a query containing mutation keywords or schema violations, it creates a specific audit record:
- `governance_tier1_eval`: The LLM's risk classification and tier selection.
- `governance_tier2_flags`: A JSON array of the deterministic flags tripped (e.g., `["BLOCK_INSERT", "MISSING_ROWNUM"]`).

This allows security and compliance teams to monitor exactly how many rogue generations the LLM attempted and how successfully the Tier 2 interceptor blocked them.

## Compliance View
The `/api/audit/logs` and `/api/audit/stats` endpoints expose this data to the React frontend, allowing administrators to filter logs by agent, status, and session ID.

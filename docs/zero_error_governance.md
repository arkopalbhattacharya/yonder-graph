# Zero-Error Governance Model

In enterprise supply chain operations, a rogue AI hallucinating a database mutation (e.g., `DELETE FROM ORD WHERE STATUS = 'P'`) is catastrophic. Yonder Graph prevents this using a strict **Two-Tier Zero-Error Governance Architecture**.

## Tier 1: Cognitive Governance (LLM-Driven)
The `GovernanceSafetyAgent` acts as a consultative policy enforcer. It evaluates the user's intent and classifies the operational risk.

**Risk Levels:**
1. `LOW_RISK_READONLY`: Status checks, tracking diagnostic queries.
2. `MEDIUM_RISK_IDEMPOTENT`: Single-record flag corrections.
3. `HIGH_RISK_MUTATION`: Multi-record or wave reprocessing.
4. `CRITICAL_RISK_STRUCTURAL`: Schema or index modifications.

**Four-Tier Remediation Policy:**
Based on the risk, the agent recommends the safest path:
- **Level 1 (MOCA Command)**: *Preferred.* Executes through Blue Yonder's validated business logic layer.
- **Level 2 (Web UI)**: Step-by-step navigation instructions for the authorized DDA (Data Driven Application).
- **Level 3 (Governed Patch)**: PL/SQL block with mandatory pre-condition checks, dry-run selects, and rollback handlers.
- **Level 4 (Dual-Control)**: Escalate to a senior SME for manual sign-off.

## Tier 2: Deterministic Hard-Guard (AST Interceptor)
LLMs cannot be fully trusted to govern themselves. Therefore, all SQL generated by the pipeline passes through a deterministic interceptor (`oracle_sql_validator.py`) before ever reaching the UI.

**Security Controls:**
1. **Mutation Blocking**: Uses `sqlparse` to scan the AST (Abstract Syntax Tree) for `INSERT`, `UPDATE`, `DELETE`, `DROP`, `ALTER`, `TRUNCATE`, `MERGE`, `EXEC`. If found, the query is hard-blocked.
2. **Row Cap Injection**: Automatically parses the AST to ensure a limit exists. If not, it injects `AND ROWNUM <= 100` (or `FETCH FIRST 100 ROWS ONLY`) to prevent unbound table scans.
3. **Schema Validation**: Validates that all referenced tables in the `FROM` or `JOIN` clauses exist as `(:Table)` nodes in the Neo4j Knowledge Graph.
4. **Parameter Sanitization**: Validates bind variables (e.g., `:ordnum`) against known regex formats to prevent SQL injection or type mismatch errors in Oracle.

*By separating the Cognitive Tier (LLM-based) from the Deterministic Tier (Code-based), Yonder Graph guarantees absolute safety regardless of which LLM provider is active.*
